# 結合テスト仕様書（画面 → API → DB）

- バージョン：v0.2（予定編集・削除をインライン方式に更新）
- 目的：画面操作から API を叩き、実際に DB にデータが入る／出る／変わる／消えるまでを通しで確認する。
- 実装：Playwright for Java（Browser + APIRequestContext ＋ DB直接確認）

---

## 方針

- 各ケース：DB初期化 → 画面操作 → **API応答確認** → **DBレコード確認** の3段階で検証
- DB確認は `SELECT` を JDBC で直接実行
- 利用者は LocalStorage に "お母さん" を事前に設定してスケジュール画面から開始する

## TC-IT-01 登録の結合

| # | 画面操作 | 期待API | 期待DB | 期待画面 |
|---|---------|---------|--------|---------|
| 01-1 | +追加 → 誰が=長女, 日付=今日, 内容="部活" → 保存 | `POST /api/schedules` 201 | `schedules` に1件（member_id=3, date=today, content="部活"） | トースト "保存しました"、今日枠長女に "部活" |
| 01-2 | +追加 → 内容空 → 保存 | APIは呼ばれない（クライアント側バリデーション） | DB変化なし | エラー表示、モーダル残る |
| 01-3 | +追加 → 内容101文字 → 保存 | `POST` 400 または クライアント側で止まる | DB変化なし | エラー表示 |

## TC-IT-02 編集の結合（インライン）

| # | 前提 | 画面操作 | 期待API | 期待DB | 期待画面 |
|---|-----|---------|---------|--------|---------|
| 02-1 | id=1, member=長女, content=部活 | 予定タップ → インライン入力欄に "部活（19時まで）" を入力 → Enter | `PUT /api/schedules/1` 200 | `content='部活（19時まで）'` 反映 | トースト「更新しました」、画面反映 |
| 02-2 | 同上 | 予定タップ → 入力欄を空にして Enter | API呼ばれない（クライアント側キャンセル） | DB変化なし | 元の "部活" に戻る |
| 02-3 | 同上 | 予定タップ → Escape | API呼ばれない | DB変化なし | 元の "部活" に戻る |

## TC-IT-03 削除の結合（✕ボタン+UNDO）

| # | 前提 | 画面操作 | 期待API | 期待DB | 期待画面 |
|---|-----|---------|---------|--------|---------|
| 03-1 | id=2, content=サッカー教室 | ✕ボタン タップ | `DELETE /api/schedules/2` 204（ソフト削除） | `deleted_at` セット | トースト「削除しました 元に戻す」、セル「予定なし」 |

| 03-3 | 同上 | 5秒以上待つ（UNDOせず） | `POST /api/schedules/2/purge` | レコード物理削除 | 変化なし（セル「予定なし」のまま） |

## 確認項目（共通）

- API レスポンスと DB 実データが一致
- 画面に表示される内容が DB の `content` と完全一致
- 400/404 が返されたときはDBが変化しない
