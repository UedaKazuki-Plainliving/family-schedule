# EX-010：非機能セキュリティ専門家（堅牢性・アクセシビリティ・パフォーマンス）

| 項目 | 値 |
|---|---|
| ラウンド | 第2ラウンド |
| 担当 | 非機能セキュリティ専門家 |
| 実施日 | 2026-04-26 |
| 観点 | 堅牢性・アクセシビリティ・パフォーマンス |

## ミッション
> セキュリティ・アクセシビリティ・操作の堅牢性について、機能的な正しさとは別の軸でアプリを検証する。特に「意図しない操作で壊れないか」と「誰でも使えるか」に焦点を当てる。

---

## 探索の流れ

### ① 仮説：ヘッダーにマウスダウンしてドラッグするとフリックとして誤検知されるのでは？

フリック操作はスクリーン上の `mousedown → mousemove → mouseup` の座標差で判定していると思われる。ヘッダーは通常操作しないエリアだが、もしヘッダー上でマウスダウンした場合も同じイベントを拾っているなら、誤フリックが発生する。特に子どもがスクロールしようとしてヘッダーを触るケースが想定される。

**手順**
1. ヘッダー（日付表示エリア）の上でマウスボタンを押したまま横方向にドラッグ
2. 画面が翌日・前日へ移動するか確認

**発見 → ET-008**
ヘッダー上からドラッグしても翌日へ移動する。フリック判定がスクリーン全体を対象にしており、ヘッダーを除外していない。ヘッダーのボタン操作中に誤フリックが起きうる。

---

### ② 仮説（ET-008 の発見から派生）：viewport に user-scalable=no が設定されているのでは？

ET-008 でフリック判定が広すぎることが判明した。この実装はモバイルブラウザのピンチズームを想定していない可能性がある。HTML の `<meta name="viewport">` に `user-scalable=no` が設定されていれば、ユーザーがズームできず WCAG 2.1 SC 1.4.4（テキストのリサイズ）に違反する。

**手順**
1. ページソースの `<meta name="viewport">` を確認
2. iPhone Safari でピンチアウト（ズームイン）を試みる

**発見 → ET-019**
`<meta name="viewport" content="..., user-scalable=no">` が設定されている。iPhone でピンチズームができない。視力が低いユーザー（シニア層）がフォントを拡大できず、WCAG 2.1 SC 1.4.4 違反。

---

### ③ 仮説（ET-019 の発見から派生）：CORS の設定は適切か？

`user-scalable=no` のような不適切な設定が残っているなら、CORS ヘッダーの設定も確認すべきだ。別オリジンからの `preflight (OPTIONS)` リクエストをどう処理しているか。

**手順**
```
curl -X OPTIONS http://localhost:8080/api/schedules \
  -H "Origin: https://evil.example.com" \
  -H "Access-Control-Request-Method: POST" -v
```

**結果 → ET-020（問題なし）**
403 で拒否。`Access-Control-Allow-Origin` に `evil.example.com` は含まれない。CORS 設定は適切。

---

### ④ 仮説：LocalStorage が破損した状態でも CORS 同様に正常に起動できるか？

CORS が問題なしなら、次はクライアント側の堅牢性を確認する。LocalStorage に壊れたデータが入った状態（他の EX-004 でも確認済みだが）でアプリが起動できるかをこの観点でも追確認する。

**手順**
1. DevTools Console で `localStorage.setItem('familySchedule.currentUser', '{broken}')` を実行
2. ページをリロード
3. JavaScript エラーでアプリが停止しないか確認

**結果 → ET-021（問題なし）**
利用者選択画面（S-01）に正常にフォールバック。try-catch で LocalStorage パースエラーをハンドリングしており、アプリが停止しない。
