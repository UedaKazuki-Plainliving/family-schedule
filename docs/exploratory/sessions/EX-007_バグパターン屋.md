# EX-007：バグパターン屋（WEB系頻出バグ・ブラックボックス）

| 項目 | 値 |
|---|---|
| ラウンド | 第2ラウンド |
| 担当 | バグパターン屋 |
| 実施日 | 2026-04-26 |
| 観点 | WEB系頻出バグ・ブラックボックス |

## ミッション
> WEB アプリで繰り返し出現するバグパターン（競合状態・非同期処理漏れ・ゴーストイベント・暗黙保存）を、実装を見ずにブラックボックスで操作し、ユーザーが意図しない動作を引き起こす欠陥を発見する

---

## 探索の流れ

### ① 仮説：削除は「ソフト削除」のはずなので、UNDO 待ち中にメンバー削除をぶつけたらどうなるか？

「元に戻す」ボタンがある = 削除は DB から消えていない（`deleted_at` フラグ方式）のはず。この状態でそのメンバーを物理削除しようとすれば、外部キー制約に引っかかるはずだ。

**手順**
1. メンバー（例：長男）の予定を作成
2. ✕ボタンで削除（ソフト削除 → UNDO 待ち状態）
3. 5 秒経過前に `DELETE /api/members/5` を送信
4. レスポンスを確認

**発見 → ET-003**
500 エラー（外部キー制約違反）。ソフト削除中のレコードが `schedules.member_id → members.id` の制約に引っかかり、メンバーを削除できない。

---

### ② 仮説（ET-003 の発見から派生）：5 秒後の auto-purge が失敗したらどうなるか？

auto-purge（`setTimeout` で 5 秒後に `DELETE /api/schedules/{id}`）が失敗した場合、ソフト削除中のレコードが永遠に残り、ET-003 と同じ状態が続く。しかも purge 失敗がユーザーに通知されなければ、ユーザーは「削除できた」と思っているのに実はされていない状態になる。

**手順**
1. DevTools の Network で `DELETE /api/schedules/*` をブロック
2. 予定を削除して 5 秒待つ
3. UI への通知・トーストを確認

**発見 → ET-010**
UI に何も表示されない。Network タブでは `(failed)` が確認できるが、ユーザーには伝わらない。サイレント無視。

---

### ③ 仮説（ET-010 の発見から派生）：auto-purge 完了（正常時）の通知もないのでは？

purge 失敗がサイレントなら、成功時も同様に通知がない可能性が高い。「削除しました」トーストが消えた後、削除が確定したのかどうかユーザーには分からない。

**手順**
1. 予定を削除
2. UNDO ボタンを押さず 5 秒待機
3. トーストが「確定しました」等に変わるか、または何か別の表示が出るか観察

**発見 → ET-007**
トーストが消えるだけで確定通知なし。削除確定をユーザーが認識できない。

---

### ④ 仮説：タッチ操作後のゴーストマウスイベントがフリック誤検知を引き起こすのでは？

モバイルブラウザは `touchend` の約 300ms 後に `mousedown → mouseup → click` のゴーストイベントを発火させる。フリック判定が `mousedown / mouseup` の座標差を見ている場合、タップ直後のゴーストイベントがフリックとして誤検知されうる。

**手順**
1. iPhone Safari（または DevTools モバイルエミュレーション）でアプリを開く
2. 予定アイテムを素早くタップ
3. タップ直後に画面が左右にスクロールしないか観察
4. DevTools の Event Listeners で `mousedown` の発火タイミングを確認

**発見 → ET-011**
タップ直後に `mousemove` が発火し、フリック判定の閾値を超えて画面が翌日・前日へ移動してしまう。

---

### ⑤ 仮説：フォームの blur イベントに保存が紐付いていれば、モーダルを閉じただけで暗黙保存される

リネーム入力欄に `blur` → 保存の実装があれば、モーダル外をタップして閉じた際に `blur` が発火して変更が保存される。ユーザーは「キャンセルした」つもりでも変更が入ってしまう。

**手順**
1. メンバー管理モーダルを開く
2. 「変更」ボタンでリネーム入力欄を表示
3. 新しい名前（例：「テスト」）を入力（Enterは押さない）
4. モーダルの背景オーバーレイをタップして閉じる
5. メンバー一覧の名前が変わっていないか確認

**発見 → ET-015**
入力途中の名前に変更されている。`blur` イベントで保存が実行されていた。
