# EX-009：UX専門家（操作性・デザイン・見やすさ）

| 項目 | 値 |
|---|---|
| ラウンド | 第2ラウンド |
| 担当 | UX専門家 |
| 実施日 | 2026-04-26 |
| 観点 | 操作性・デザイン・見やすさ |

## ミッション
> 実機（iPhone 13 サイズ）でアプリを操作し、タップしにくい・見にくい・意図が伝わらないといった操作性・可読性の問題を発見する。Apple HIG および WCAG 2.1 のガイドラインを判断基準とする。

---

## 探索の流れ

### ① 仮説：✕ボタンのタップ領域が小さすぎるのでは？

スケジュールアイテムの✕ボタンは小さいアイコンに見える。Apple HIG は最小タップ領域を 44×44pt 推奨とするが、CSS を見ると実装が小さい可能性がある。子どものユーザー（長女・次女・長男）が操作することを考えると誤操作につながる。

**手順**
1. DevTools で `.schedule-item-delete` の `width` / `height` を確認
2. iPhone 実機でタップして操作しやすいか体感

**発見 → ET-001**
`width: 20px; height: 20px` → Apple HIG の 44px を大きく下回る。実機でも隣の予定テキストを押してしまう誤タップが発生。

---

### ② 仮説（ET-001 の発見から派生）：他のボタンも同様にタップ領域が不十分な箇所があるのでは？

✕ボタンが 20px なら、他のボタンも同様に小さい可能性がある。削除確認ダイアログのボタンも確認すべきだ。また、ラベルが「はい / いいえ」だと「何に対してのはい/いいえか」が不明瞭になることが多い。

**手順**
1. 予定の✕ボタンをタップして削除確認ダイアログを表示
2. ダイアログのボタンラベルを確認
3. ラベルが操作の意図を正しく伝えているか評価

**発見 → ET-017**
ボタンラベルが「いいえ / はい」。「削除する / キャンセル」など動詞を含めた明確なラベルが UX 的に望ましい。現状では「はい」が何を意味するか（削除の確認か、中止の確認か）が瞬時に判断しにくい。

---

### ③ 仮説：現在のユーザー名ボタンのフォントサイズはモバイル基準を満たしているか？

ヘッダーの現在のユーザー名ボタンは小さい文字に見える。WCAG 2.1 および多くのモバイルガイドラインは本文フォントを 16px 以上を推奨する。14px 以下だと小さい画面で読みづらく、高齢ユーザー（おじいちゃん・おばあちゃんが将来メンバーに加わった場合など）には厳しい。

**手順**
1. DevTools で `#btn-switch-user`（またはユーザー名表示要素）の `font-size` を確認
2. iPhone の表示倍率との関係も考慮

**発見 → ET-018**
`font-size: 14px`。WCAG 2.1 推奨の 16px に達していない。特にシニアユーザーが将来利用する場合は可読性が問題になる。
